AppImage or package?

AppImage

Runs anywhere, installs nothing. One file you make executable and double-click. Best if you're on an older distro, aren't sure what you're running, or just want to try it. You keep the file wherever you like.

.deb / .rpm

Proper install, menu entry, litranite command. Needs WebKitGTK 4.1 from your distro — Ubuntu 22.04+, Debian 12+, Fedora 38+ have it. Install it with apt / dnf / zypper, never dpkg -i: see step 2.

1

The AppImage route

Download the .AppImage, then mark it as runnable — either right-click → Properties › Permissions › Allow executing file as program, or in a terminal in the folder you downloaded it to:

$ chmod +x Litranite_*.AppImage

Then run it by double-clicking, or:

$ ./Litranite_*.AppImage

If it complains about FUSE (“dlopen(): error loading libfuse.so.2”), either install it — sudo apt install libfuse2 on Ubuntu 22.04+ — or skip FUSE altogether:

$ ./Litranite_*.AppImage --appimage-extract-and-run
2

The package route — use apt, not dpkg

Run the command for your distro in the folder you downloaded the file to. The ./ matters: without it your package manager goes looking for a package by that name on the internet instead of the file on your disk.

Debian · Ubuntu · Mint · Pop!_OS

$ sudo apt install ./Litranite_*.deb

Fedora · RHEL

$ sudo dnf install ./Litranite-*.rpm

openSUSE

$ sudo zypper install ./Litranite-*.rpm

Don't use sudo dpkg -i (or rpm -i). They install Litranite but not the libraries it needs — libwebkit2gtk-4.1-0 and libgtk-3-0. The app lands in your menu and then refuses to open, with nothing to explain why. apt, dnf and zypper pull the dependencies in as well. If you already used dpkg, this repairs it: sudo apt --fix-broken install

Afterwards Litranite is in your applications menu, and the command litranite works in any terminal.

3

Installed, but it won't open?

This is the common one on Linux, and it isn't your fault. WebKitGTK's DMABUF renderer breaks on a long list of setups — NVIDIA's proprietary driver, some Intel/Mesa versions, most virtual machines, and plenty of Wayland sessions. The window never appears, or opens blank. Start it once like this:

$ WEBKIT_DISABLE_DMABUF_RENDERER=1 litranite

If that works, the renderer was the problem. From 1.5.0 Litranite sets this itself, including when you start it from the menu — so you only need it on 1.4.0 and earlier.

For the AppImage, put the same thing in front of the file:

$ WEBKIT_DISABLE_DMABUF_RENDERER=1 ./Litranite_*.AppImage

Still nothing? Fall back to software rendering, which works almost everywhere but scrolls less smoothly:

$ WEBKIT_DISABLE_COMPOSITING_MODE=1 WEBKIT_DISABLE_DMABUF_RENDERER=1 litranite

If something still goes wrong

Run litranite from a terminal first — whatever it prints is the real clue.

It installed, but nothing happens when I click it+
Nine times out of ten this is the graphics renderer — try step 3. If running it in a terminal prints something about libwebkit2gtk being missing, you installed with dpkg -i and the dependencies never came: run sudo apt --fix-broken install, or reinstall with sudo apt install ./Litranite_*.deb.
The window opens but it's blank or white+
Same cause as above — the page renders into a surface your driver can't hand over. WEBKIT_DISABLE_DMABUF_RENDERER=1 litranite, and if that isn't enough add WEBKIT_DISABLE_COMPOSITING_MODE=1. Common on NVIDIA's proprietary driver and inside VirtualBox or VMware.
“litranite: command not found”+
The package isn't installed — that command only exists after the .deb or .rpm route. If you're using the AppImage, run the file itself: ./Litranite_*.AppImage from the folder it's in.
“Permission denied” when I run the AppImage+
It isn't marked executable yet: chmod +x Litranite_*.AppImage. If the file sits on a drive mounted with noexec (some external or Windows partitions), move it into your home folder first.
“dlopen(): error loading libfuse.so.2”+
AppImages use FUSE 2, which newer distros don't install by default. Either sudo apt install libfuse2, or skip it entirely with ./Litranite_*.AppImage --appimage-extract-and-run.
The AppImage doesn't show up in my applications menu+
That's expected — an AppImage is just a file, it doesn't register itself. Keep it somewhere sensible like ~/Applications and let your desktop add it (GNOME and KDE both offer to), or use the .deb/.rpm, which do add a menu entry.
Does it need WebKitGTK 4.1? My distro only has 4.0+
Yes — the packages depend on libwebkit2gtk-4.1-0 and libgtk-3-0. Ubuntu 22.04+, Debian 12+ and Fedora 38+ have it. On anything older, use the AppImage instead.
Where is my work kept, and how do I uninstall?+
Your notes and annotations live in ~/.local/share/com.litranite.app. Remove the app with sudo apt remove litranite (or sudo dnf remove litranite); delete the AppImage file if that's the route you took. Your data folder stays until you delete it yourself — export a backup first if you might come back.
Wayland, NVIDIA, or a VM — anything special?+
All three are exactly where the renderer flag in step 3 earns its keep. On Wayland you can also force the X11 path with GDK_BACKEND=x11 litranite if windows behave oddly.
